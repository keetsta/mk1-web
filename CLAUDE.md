# mk1-web

веб-терминал и лидерборд визитки mk-1. самостоятельная сборка обслуживает `/mk1/` и `/mk1/top/`. прошивка и протокол описаны в подмодуле `shell/`. сборка и автодеплой описаны в [README](README.md).

## сборка и проверка

- используй node.js 24. после правок запусти `npm test` и `npm run build -- --base /mk1/`.
- файлы протоколов, UF2, PICOBOOT и wasm тестируются в node со стиранием типов. держи эти модули совместимыми с прямым запуском TypeScript.
- `src/mk1/shell/mk1-shell.wasm` отслеживается в git. после обновления gitlink пересобери его через `npm run wasm`. CI собирает wasm из закреплённого коммита, локальный `MK1_SHELL_DIR` для экспериментов.
- развёртывание только из `main`. web-архив включает страницы и assets. прошивка и api обслуживаются отдельно.
- геометрию и слои платы обновляй через `npm run geometry` из `mk1-card`. результат хранится в git. интерфейс проверяй через `tools/shot.mjs` на разных размерах экрана и с уменьшением движения.

## usb и лидерборд

- фильтр serial по VID Raspberry Pi широкий. `hello` сообщает протокол и версию. serial и BOOTSEL используют разные разрешения, связь с целевым устройством нужно сохранять до начала записи.
- для автоматического перехода на 1200 бод нужна пара `hello` и chip id. сверяй id с выбранным BOOTSEL. до стирания исключай область сохранений из образа. после записи проверяй байты чтением.
- sha256 связывает загруженный файл с манифестом. релизный манифест и выбранный локальный uf2 имеют разные источники доверия.
- `BoardReader` узнаёт вывод `top` в сыром serial-потоке. токен и решения не должны попадать в логи, аналитику или тестовые снимки. POST выполняется после явного подтверждения.
- API принимает байткод с подписью и возвращает вычисленные метрики. хранение прогресса try it в localStorage относится только к эмулятору.

## интерфейс

- токены и классы карточек берутся с keetsta-website, локальная копия в `src/demo/site.css`. интерфейс на английском, строчными. используй иконки из `icons.ts`, плоские поверхности и нейтральные тени.
- переиспользуй `Unfold`, `Smooth` и `Swap` для раскрытия и смены состояния. учитывай уменьшение движения. переходы между страницами оставляют ссылки нативными.
- свёрнутый терминал остаётся смонтированным и `inert`, чтобы сохранить ранний вывод. при раскрытии он принимает фокус. проверь ввод, XTerm и возврат в ожидание при правках жизненного цикла.
- 3D-превью имеет svg-запасной вариант. светодиоды плоские, камера не следует за курсором.
